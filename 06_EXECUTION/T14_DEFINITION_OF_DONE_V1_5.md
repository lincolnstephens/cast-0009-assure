## What the gate does not check

- **The last-manager rule on the live site.** While the gate's own manager account is enabled there are two active managers, so the rule cannot be driven live without risking locking out the demo operator. The unit test `accounts.test.ts` proves it.
- **Invalid user creates.** A manager with an organisation, or a client without one, would leave a stray account on the live store if the product wrongly accepted it, so the gate does not send them. The unit tests prove both are refused.
- **Email addresses from the restricted file.** It holds none today, so the restricted-term checks cover the three names only.
